# Fable documentation benchmark

This benchmark tests whether explicitly targeting instructions at AI agents changes how strongly an LLM follows them. It uses five entirely fictional fables rather than programming APIs, SDKs, code generation, or technical-domain knowledge. Each fable describes two distinct, equally valid three-step procedures for reaching the same goal. The document recommends one procedure, while the task asks the model to choose and explain one complete procedure.

The design separates four effects: explicit audience targeting, isolation in a dedicated block, generic recommendation framing, and semantic compression. A model can be correct while choosing either valid path, so world correctness and preferred-path compliance are reported separately.

## Conditions

Each world has six versioned Markdown artifacts:

- A: full tale with an isolated `For AI agents and LLMs` block.
- B: full Markdown source with the same AI-targeted block.
- C: concise ordinary Markdown preserving both paths, recommendation, order, and no-mixing constraint.
- D: full tale with the recommendation embedded in ordinary prose and no AI audience language.
- E: full neutral tale describing both valid procedures without recommending one.
- F: the isolated block from A with only the heading changed to `Recommended approach`.

The nominal preferred path alternates across worlds. Source definitions live in `worlds/*/source.json`; the six artifacts and proposition manifests are generated by `benchmark.artifacts`. A/F validation normalizes the audience heading and requires equality.

## Local setup and validation

Python 3.10+ is required. Runtime dependencies are standard-library only; install the optional test dependency with `python -m pip install -e '.[dev]'` if needed.

```bash
python -m benchmark validate
python -m pytest
```

`validate` rebuilds artifacts, checks that every path entity appears in every artifact, checks path lengths, and verifies A/F equivalence after the intended heading substitution. It never calls OpenRouter.

Inspect the exact system prompt, documentation, and task supplied to a model:

```bash
python -m benchmark inspect --world bellwater --condition A
```

## OpenRouter runs

Real API calls require an explicit `run` command and `OPENROUTER_API_KEY`. Every call is independent, the condition/world order is shuffled using the recorded seed, temperature is zero where supported, and raw responses are stored in JSONL.

Smoke test:

```bash
export OPENROUTER_API_KEY='...'
python -m benchmark run \
  --models anthropic/claude-sonnet-4.6 \
  --world bellwater \
  --conditions A B C D E F \
  --runs 2 \
  --output results/smoke.jsonl
```

Full single-model experiment (600 calls):

```bash
python -m benchmark run \
  --models anthropic/claude-sonnet-4.6 \
  --worlds bellwater orchard messenger lantern well \
  --conditions A B C D E F \
  --runs 20 \
  --output results/sonnet.jsonl
```

Generate reports:

```bash
python -m benchmark report results/sonnet.jsonl
```

## Deterministic scoring

The evaluator matches each world’s distinctive entities and verifies their order. It classifies:

- `world_correct`: one complete valid procedure, either old or new.
- `preferred_path`: the designated recommended procedure with no alternative entities.
- `alternative_path`: the other complete procedure with no preferred entities.
- `mixed_path`: entities from both procedures are combined.
- `invalid_answer`: incomplete, mixed, invented, both-options, or otherwise non-procedural output.
- `sequence_correct`: one complete path appears in the required order.

No LLM judge is used. Minor wording variation is tolerated because matching uses distinctive normalized entity phrases. The raw output remains available for independent rescoring.

## Interpretation and limitations

The primary outcome is preferred-path compliance over all trials and among world-correct trials. Reports include world-level and aggregate tables, token counts, compression-related artifact sizes, latency, cost, Wilson intervals, and Fisher comparisons for A/E, B/E, C/E, D/E, F/E, A/F, A/D, and B/C.

The benchmark is deliberately small and fictional. Repeated temperature-zero calls can be identical, provider routing can vary, and five worlds cannot establish a universal claim about models or documentation. The artifacts must be finalized before a real experiment; do not tune them after examining results. If wording changes, create a new commit/version and rerun validation.
